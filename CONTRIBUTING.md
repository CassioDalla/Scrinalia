# Contributing to Scrinalia

Thanks for looking. This is a system for archivists to catalogue and enrich archival descriptions;
the design decisions are documented, and the document that matters most before you touch the code is
[`AGENTS.md`](AGENTS.md) — it is the list of rules that are easy to break and expensive to re-derive.

## Before you start

- **Security problems do not belong here.** Follow [`SECURITY.md`](SECURITY.md) and report privately.
- **Open an issue first for anything that is not a small fix.** A change to a route's shape, to a
  domain's rules or to the database schema is worth agreeing on before it is written — the project
  has opinions, and most of them have an ADR behind them.
- Read the [ADRs](docs/adr/) that touch what you are changing. If your change contradicts one, say so
  in the issue; that is a conversation about the decision, not a detail of the diff.

## Setting up

```bash
uv sync                        # Python 3.12, managed by uv
bun install                    # packages and scripts; Vite is the bundler
docker compose up -d           # PostgreSQL + MinIO
uv run alembic upgrade head    # the schema is owned by Alembic
uv run pre-commit install      # ruff + basedpyright on every commit
```

The integration tests need their own database — see the **Tests** section of [`AGENTS.md`](AGENTS.md)
for the port and the `TEST_DATABASE_URL` override. Never point the test suite at a database you care
about: it drops the schema on teardown.

## The checks a pull request has to pass

Run these from the repository root before opening the PR; they are what CI runs.

```bash
uv run ruff check . && uv run ruff format --check .
uv run basedpyright
uv run pytest
bun run contract               # regenerates openapi.json + the TypeScript client
bun run --cwd apps/curator typecheck && bun run --cwd apps/curator lint && bun run --cwd apps/curator build
uv run alembic check           # fails on model/migration drift
```

Two of these are easy to forget and both fail CI:

- **the contract is generated and committed.** A route or schema change must include the regenerated
  `packages/api-contract/openapi.json` and `apps/curator/src/api/schema.d.ts`;
- **`alembic check` must report no drift.** A model change without a migration is a broken install.

## Conventions

- **Conventional Commits**, with the body explaining *why* the change is what it is. Read the existing
  history: the messages are part of the documentation here.
- **Code and comments in English.** Portuguese is only for text an end user reads — the curator UI,
  and the `message` an API response carries. This is not a style preference; see the Language section
  of `AGENTS.md`.
- **The API is the contract.** The front never builds a URL by hand and never queries the database:
  it goes through the generated client. ESLint bans the `fetch` global for that reason.
- **A test that would pass with the bug reintroduced is not a test.** The suite has several examples
  of pinning a behaviour by making the failure mode visible (the corrupted path, the decoy hash, the
  route classification partition); follow them.
- **Database changes are migrations**, autogenerated and then read — the autogenerator creates unnamed
  foreign keys and misses things a human has to fix.

## Sign your commits (DCO)

Every commit must carry a `Signed-off-by:` line. Add it automatically:

```bash
git commit -s
```

That is the [Developer Certificate of Origin](https://developercertificate.org/): by signing you
certify that you wrote the change, or have the right to submit it, and that it may be distributed
under this project's license. It is **not** a copyright assignment — you keep the copyright of your
contribution. There is no CLA, and the project does not need one.

CI checks the trailer on every commit of a pull request, so a missing sign-off fails the build rather
than being caught in review.
